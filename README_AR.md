# صيدلية المركز — MySQL محلي وCloudflare

**لتشغيل FreeSQLDatabase على MySQL5.5.62 اقرأ README_MYSQL55_AR.md أولًا؛ مسار Cloudflare له يستخدم بوابة HTTPS إلى Express، وليس Hyperdrive.**

هذه النسخة تستبدل اتصال Firebase بواجهات API على Express وقاعدة MySQL. نفس الخادم يعمل على Windows وعلى Cloudflare Workers، مع واجهة React/PWA نفسها. قاعدة الإنترنت وقاعدة المكتب مستقلتان؛ لا توجد مزامنة تلقائية بينهما. لا تؤكد الواجهة الصرف قبل نجاح معاملة الخادم.

## ما تغير

- كلمات مرور الحسابات محفوظة **نصية في عمود `users.password` بناءً على طلب صاحب المشروع**. تُنقل كلمات المرور الأصلية دون تغيير؛ التحقق من الدخول داخل الخادم، ولا ترسل قوائم كلمات المرور إلى المتصفح.
- جلسة الدخول Cookie من نوع HttpOnly. كلمات مرور MySQL ومفاتيح الخدمات لا تدخل حزمة React.
- الصرف وخصم المخزون وسجل التدقيق وتأكيد الجرعة عملية واحدة داخل InnoDB، مع منع المخزون السالب وتكرار الطلب وتكرار الجرعة المجدولة في اليوم نفسه.
- المبرمج ومدير النظام فقط يديران الوحدات والفئات. الفني لا يصرف الأدوية المقيدة. الأدوية المنتهية تُرفض داخل الخادم.
- تعديلات السجلات تستخدم `_version` لاكتشاف التعديلات المتعارضة. البيانات الطبية الموجودة في الذاكرة تُمسح عند تسجيل الخروج، ولا توجد كتابة ناجحة وهمية إلى LocalStorage.
- تبقى الحقول الطبية الإضافية وجداول الجرعات داخل JSON في جداول MySQL للحفاظ على توافق البيانات. كميات المخزون والأسعار والتواريخ وحسابات المستخدمين والجلسات وتأكيدات الصرف لها أعمدة محددة الأنواع. لم يتم الادعاء بتحويل كل الحقول المتداخلة إلى جداول مستقلة.

## 1. تشغيل Windows على جهاز واحد أو شبكة

المتطلبات: Node.js 24 LTS وMySQL Server 8.0 أو 8.4. هذه حزمة مصدر وتشغيل؛ ليست مثبت EXE ولا تتضمن خادم MySQL.

1. فك الحزمة في مجلد مثل `C:\PharmaCenter`.
2. نفذ `sql/create_database.sql` من MySQL Workbench لإنشاء `pharma_sh_center`.
3. شغّل `windows/Install.cmd`؛ يثبت الحزم ويبني الواجهة وينشئ `.env` من المثال.
4. افتح `.env` وضع بيانات MySQL الفعلية. استخدم حساب إعداد له صلاحية CREATE/ALTER عند إنشاء الجداول. بعد الإعداد استخدم حساب التطبيق المحدود الموضح في ملف SQL.
5. لقاعدة جديدة فارغة، ضع `ADMIN_EMAIL` و`ADMIN_PASSWORD` ثم نفذ:

```powershell
npm run db:init
```

6. شغّل `windows/Start.cmd`. افتح `http://localhost:3000` وسجل الدخول بالحساب الذي اخترته.
7. لتشغيل أجهزة الموظفين: شغّل `windows/Show-Network-Address.cmd` على الجهاز الرئيسي. افتح مثلًا `http://192.168.1.20:3000` من أجهزة الشبكة. استخدم عنوان IPv4 الحقيقي، وليس المثال. اسمح للتطبيق على الشبكة الخاصة في جدار حماية Windows عند الحاجة.

يبقى MySQL على الجهاز الرئيسي؛ أجهزة الموظفين تصل إلى Express فقط. لا تفتح منفذ MySQL لأجهزة الموظفين. يعمل النظام المحلي دون الإنترنت عند بقاء الشبكة والخادم متاحين. تثبيت PWA خارج localhost يحتاج HTTPS؛ فتح الموقع العادي عبر LAN HTTP متاح.

المنفذ الافتراضي `3000` ويمكن تغييره في `.env`. اترك `APP_ORIGIN` غير محدد عند استخدام عدة عناوين محلية. في حالة HTTPS اضبط `COOKIE_SECURE=true` و`APP_ORIGIN` على رابطك الحقيقي.

## 2. نقل بيانات Firebase الحالية

الكود لا يستطيع استنتاج سجلات قاعدة Firebase من الريبو. يلزم ملف JSON فعلي من نسختك الأصلية؛ لا ترفع بيانات المرضى أو كلمات المرور إلى GitHub.

الصيغة المدعومة هي `{ "collections": { "medicines": [...], "users": [...], ... } }` أو كائن مجموعات مباشر. تصدير Firestore الثنائي من Google Cloud لا يُستورد مباشرة بهذه الأداة. التصدير القديم من التطبيق قد يكون ناقصًا: تحقق خصوصًا من `doctors` و`custom_side_effects`، وأكمل المجموعات الناقصة من المصدر قبل الانتقال النهائي. الأداة تقارن ما قدمته لها، ولا تستطيع إثبات اكتمال ملف المصدر دون مقارنته بـFirebase.

**استخدم قاعدة MySQL فارغة، ولا تنشئ الحساب الأول قبل استيراد الحسابات الأصلية:**

```powershell
npm run db:init -- --schema-only
npm run db:import -- C:\Backups\firebase-export.json
npm run db:import -- C:\Backups\firebase-export.json --apply
```

الأمر الثاني فحص فقط. الأمر الثالث ينفذ الاستيراد داخل معاملة ويرفض الهدف غير الفارغ ويتحقق من أعداد السجلات. يحافظ على المعرّفات والحقول الإضافية وكلمات المرور النصية وأدوار الحسابات وحالاتها. لا يستورد جلسات الدخول القديمة؛ يجب تسجيل الدخول مجددًا. لا يتم تفسير نص وصف الجرعة طبيًا أثناء النقل؛ الجرعات القديمة التي ليس لها مقدار رقمي تحتاج مراجعة قبل صرفها المجدول.

إذا لم يتضمن المصدر حساب مبرمج صالحًا، حدد حسابًا جديدًا في `.env` ثم:

```powershell
npm run db:init -- --bootstrap-only
```

لإعادة ضبط حساب موجود عمدًا استخدم `--bootstrap-only --reset-admin`؛ هذا يضبط الحساب المحدد في `ADMIN_EMAIL` كمبرمج بكلمة المرور النصية الموجودة في `ADMIN_PASSWORD`.

## 3. نشر Cloudflare وربط MySQL أونلاين

Cloudflare يشغّل الواجهة وExpress عبر Workers. MySQL يكون لدى مزود خارجي. Hyperdrive يربط Workers بقاعدة MySQL؛ لا ينشئ قاعدة بيانات بدلًا عنها.

1. أنشئ قاعدة MySQL أونلاين وخذ عنوانها ومنفذها واسمها واسم مستخدمها وكلمة المرور. تحقق أن المزود يسمح باتصال Hyperdrive وبـTLS وأن خطته مناسبة للاستخدام؛ لا توجد وعود بأن كل الخدمات مجانية أو غير محدودة.
2. استخدم `.env` مؤقتًا مع إعدادات القاعدة الأونلاين و`DB_SSL=true` وشهادة CA عند طلب المزود، ثم أنشئ الجداول واستورد البيانات كما في الخطوات السابقة. **راجع اسم القاعدة قبل أي أمر.**
3. سجل الدخول إلى Cloudflare:

```powershell
npx wrangler login
```

4. أنشئ Hyperdrive من لوحة Cloudflare باختيار MySQL وإدخال الاتصال الخارجي وتفعيل التحقق من TLS. أوقف تخزين نتائج الاستعلامات (Query caching) لهذا التطبيق الطبي لتجنب قراءة مخزون أو جلسات قديمة. لا تضع كلمة مرور قاعدة البيانات في `wrangler.jsonc`.
5. ضع معرف Hyperdrive الحقيقي في `wrangler.jsonc` بدل `REPLACE_WITH_YOUR_HYPERDRIVE_ID`. استخدم `CENTER_TIMEZONE` المناسب للمركز؛ الافتراضي `Asia/Riyadh`.
6. عند استخدام التحليل الخارجي فقط، ضع مفتاحه في Worker Secret:

```powershell
npx wrangler secret put GEMINI_API_KEY
```

7. افحص الحزمة ثم انشر:

```powershell
npm run cloudflare:check
npm run cloudflare:deploy
```

النشر يستخدم Workers Static Assets للواجهة وExpress لمسارات `/api/*` من نفس الرابط. لا تنشر `dist` وحده على Pages ثم تتوقع أن يعمل الخادم. Cookie السحابة تستخدم HTTPS وSecure تلقائيًا. يمكن إضافة `APP_ORIGIN` في متغيرات Worker على شكل `https://your-domain.example` بعد تحديد الرابط النهائي.

لا تضع بيانات قاعدة الإنترنت داخل `VITE_*` أو ملفات الواجهة. إذا أردت المكتب والموقع على نفس البيانات، افتح الرابط السحابي من المكتب أيضًا؛ يلزم الإنترنت. لم تنفذ مزامنة بين قاعدتين مستقلتين.

## 4. النسخ الاحتياطي والاستعادة

- زر التصدير داخل البرنامج: بيانات البرنامج دون كلمات مرور المستخدمين، ودون مفاتيح إشعارات سرية أو جلسات نشطة. الاستيراد من الواجهة **إضافي فقط** ويرفض المعرّفات الموجودة؛ لا يمسح القاعدة ولا يستعيد حسابات الدخول. للعودة الكاملة استخدم نسخة الخادم في قاعدة فارغة.
- نسخة خادم كاملة تشمل كلمات المرور النصية ومفاتيح القنوات وملفات PDF:

```powershell
npm run db:export -- C:\Backups\pharma-full-2026-11-06.json
```

الملف يحتوي بيانات حساسة؛ احفظه في مكان مخصص خارج مجلد الموقع والمستودع. الأمر يرفض الكتابة فوق ملف موجود. استعده بأداة `db:import` إلى قاعدة فارغة ثم قارن الأعداد. الجلسات النشطة مستثناة عمدًا من النسخ.

## 5. الاختبارات وحدود التحقق

```powershell
npm test
npm run lint
npm run cloudflare:check
```

اختبارات MySQL تحتاج قاعدة تجريبية منفصلة اسمها مثل `pharma_ci_test`؛ يتم تفريغ جداولها أثناء الاختبار:

```powershell
$env:TEST_DATABASE_URL="mysql://test_user:test_password@127.0.0.1:3306/pharma_ci_test"
npm run test:integration
```

اختبارات التكامل تفحص الدخول والصلاحيات والصرف المتزامن ومنع التكرار والصلاحية والتعارضات وتخزين كلمة المرور نصيًا والنسخ والاستيراد. سير GitHub Actions يشغّل الاختبارات مع MySQL 8.4 ثم يفحص حزمة Cloudflare. اختبار حزمة Worker محليًا ليس إثباتًا للنشر أو اتصال Hyperdrive بقاعدة حقيقية.

بوابات الرسائل المدعومة حاليًا: UltraMsg وCallMeBot وGoogle Apps Script وWAPilot/WAutopilot على نطاقاتها المعتمدة. روابط الوكلاء المخصصة الأخرى تحتاج إضافة نطاقها إلى `backend/outbound.ts` بعد المراجعة.

الخدمات الخارجية مثل البريد والواتساب والتحليل تحتاج إعدادات صالحة واختبارًا على حساباتك؛ لم يتم إرسال رسائل فعلية أثناء التطوير. تشغيل تقارير التنبيه من الواجهة ليس جدولة خلفية مضمونة عند إغلاقها. مشاركة PDF من هذه النسخة تتطلب جلسة مستخدم مخول، ولا تقدم رابطًا عامًا لبيانات المرضى.

المراجع الرسمية: https://developers.cloudflare.com/workers/tutorials/deploy-an-express-app/ و https://developers.cloudflare.com/hyperdrive/examples/connect-to-mysql/
