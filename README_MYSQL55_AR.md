# تشغيل البرنامج مع FreeSQLDatabase — MySQL 5.5.62

هذه النسخة 1.1 تدعم قاعدة `sql12840041` على MySQL 5.5.62، وتستمر في دعم قاعدة Windows السابقة على MySQL 8.0/8.4. لا تعدّل قاعدة Windows أو تستبدل ملفات إعدادها أثناء تجربة الاتصال الأونلاين؛ فك الحزمة المحدثة في مجلد منفصل.

## ما تغير

- البيانات الطبية تخزن JSON كنص LONGTEXT في مخطط MySQL55؛ التحويل والتحقق داخل التطبيق، دون دوال JSON من السيرفر.
- الوحدات والفئات لها عمود اسم عادي وفهرس فريد، وتحديث الأدوية المرتبطة يتم داخل معاملة واحدة.
- تعديل دقة التواريخ وفهارس الجرعات لحدود MySQL5.5، مع منع تكرار الجرعة بمفتاح SHA-256 مشتق من المستفيد والجرعة وتاريخ المركز.
- كلمات المرور تظل نصية كما طلبت. لا تغير كلمات مرور الحسابات المستوردة.
- الاستعلامات مشتركة؛ الخادم يتعرف على الأعمدة الموجودة، فلا يلزم تحويل قاعدة Windows القديمة إلى LONGTEXT.

## الخطوة الأولى: استيراد بيانات الموقع

استخدم الحزمة المحدّثة `sql12840041_import.zip` التي تحتوي `sql12840041_mysql55.sql`. لا تستخدم ملف MySQL8 القديم.

1. افتح اتصال Pharma Online في Workbench وتأكد من ظهور `sql12840041` ونسخة 5.5.62.
2. تأكد أن قاعدة الموقع فارغة؛ إذا وجدت جداول أو بيانات، لا تحذفها أو تعِد الاستيراد قبل مراجعتها.
3. File > Open SQL Script، ثم اختر `sql12840041_mysql55.sql` ونفذ الملف كاملًا بزر البرق.
4. الملف لا ينشئ قاعدة جديدة ولا يستخدم إجراءات مخزنة أو حذف جداول. تعليمات INSERT مجمعة في حزم أصغر من 121 كيلوبايت لتناسب الحدود القديمة.
5. عند حدوث خطأ توقف؛ لا تفترض أن الاستيراد كله تراجع تلقائيًا، ولا تعِد تشغيل الملف فوق بيانات جزئية. الملف يستخدم معاملة، لكن برنامج الاستيراد قد يكمل بعد الأخطاء حسب إعداده.
6. راجع النتائج النهائية: medicines=247، residents=146، dispense_records=1484، stock_audit_logs=1675، users=12.

البيانات هي نسخة JSON المرفوعة سابقًا، وليست نسخة من آخر تعديلات Windows بعد ذلك. حساب د. تامر المكرر حُلّ سابقًا، مع حفظ معرفيه كبيانات مرجعية. الأطباء غير موجودين في ملف المصدر، والأعراض الجانبية الست استخرجت من مستند settings.

## الخطوة الثانية: تشغيل Express مع قاعدة الموقع

1. فك حزمة البرنامج الجديدة في مجلد منفصل مثل `C:\PharmaOnline`، وشغّل `windows\Install.cmd`.
2. افتح `.env` بجانب `package.json`، وانسخ إعدادات `.env.freesql.example` ثم ضع اسم مستخدم قاعدة الموقع وكلمة مرورها، وليس بيانات قاعدة Windows:

```env
DB_COMPAT=mysql55
DB_HOST=sql12.freesqldatabase.com
DB_PORT=3306
DB_NAME=sql12840041
DB_USER=اسم_مستخدم_قاعدة_الموقع
DB_PASSWORD=كلمة_مرور_قاعدة_الموقع
PORT=4500
HOST=0.0.0.0
COOKIE_SECURE=false
CENTER_TIMEZONE=Asia/Riyadh
```

3. ملف المثال يطلب `DB_SSL=true` للتحقق من TLS. دعم TLS وشهادته على حساب الاستضافة لم يُفحص. إذا ظهرت مشكلة SSL، أرسل نص الخطأ دون كلمة المرور؛ لا يخفّض البرنامج إعدادات TLS تلقائيًا، وقد يلزم الرجوع إلى مزود الخدمة بشأن ما يدعمه.
4. لا تشغّل `Initialize-Empty-Database.cmd` بعد استيراد حساباتك. شغّل `windows\Start.cmd` وافتح `http://localhost:4500`.
5. سجل الدخول بحسابك وكلمة مروره الأصلية. يحتاج التشغيل اتصال إنترنت لأن القاعدة على الموقع.

إذا بدأ Express برسالة تشغيل لكن فشل `/api/health`، راجع عنوان السيرفر والمنفذ وبيانات المستخدم وسياسة TLS قبل استيراد أي بيانات إضافية. الإعداد `DB_COMPAT=mysql55` يختار مخطط الإنشاء القديم عند استخدام أدوات CLI فقط؛ لا يغير بيانات موجودة.

## Cloudflare مع هذا الإصدار القديم

مسار Hyperdrive السابق مخصص للإصدارات المدرجة من MySQL5.7 وما بعدها؛ لا تعتمد عليه لقاعدة5.5.62. أضيف مسار مختلف:

واجهة Cloudflare + بوابة HTTPS → خادم Express يعمل باستمرار → MySQL لدى FreeSQLDatabase.

هذا يتطلب خادم Express على Windows أو استضافة Node.js يمكن الوصول إليها عبر HTTPS. استضافة قاعدة البيانات وحدها لا تشغّل Express. لا يعني هذا أن البرنامج أصبح مستقلًا بالكامل على Workers مع MySQL5.5.

عندما يتوفر رابط HTTPS ثابت لـExpress:

1. اضبط `APP_ORIGIN` في إعداد Express على رابط واجهة Cloudflare، و`COOKIE_SECURE=true` للواجهة عبر HTTPS.
2. ضع أصل HTTPS لخادم Express في متغير Worker `API_ORIGIN` (مثل `https://api.example.com`، دون مسار):

```powershell
npx wrangler secret put API_ORIGIN --config wrangler.mysql55.jsonc
npm run cloudflare:mysql55:check
npm run cloudflare:mysql55:deploy
```

الواجهة ومسارات `/api/*` تكون من رابط Cloudflare نفسه. البوابة تمرر Cookie وOrigin ومفاتيح الطلبات، ولا تضع بيانات دخول MySQL في المتصفح. لا تضف CORS عامًا ولا تنشر كلمة المرور في GitHub.

لم يُنشأ أو يُنشر خادم HTTPS فعلي أو حساب Cloudflare أثناء هذا التعديل. يمكن تجهيز ذلك بعد نجاح الاستيراد والاتصال بقاعدة الموقع. مستخدمو MySQL8 يستمرون في مسار Hyperdrive الأصلي وفق README_AR.md.

## حدود التحقق

تم اختبار مخطط واستعلامات التوافق على MySQL5.5.62 معزول بنفس نسخة المحرك التي ظهرت في صورتك، وليس على حسابك الفعلي. ملفات البيانات احتفظت بالمحتوى وكلمات المرور النصية. بلغت مساحة جداول وفهارس بياناتك في الاختبار 4,096,000 بايت تقريبًا؛ إذا كانت حصة حسابك 5MB فالمساحة المتبقية محدودة، وقد يختلف احتساب المزود. قيود مساحة حسابك وصلاحياته واتصاله وTLS ما زالت تحتاج تحققًا على الخدمة. لا تتضمن الحزمة بيانات دخول استضافتك.
